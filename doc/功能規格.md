# 現買改資買／下單改類 — 功能規格

> 對齊現行原型：`index.html`（客戶端）、`cms-現買改資買.html`（後台 CMS）  
> 狀態：Demo／前端假資料；標「⚠ 待確認」者為正式系統尚需定案  
> 更新日期：2026-09-15

---

## 0. 產品範圍

| 端 | 頁面／檔案 | 定位 |
|---|---|---|
| 客戶端 | `index.html` | 用戶線上申請現股買進改融資、查看申請紀錄 |
| 後台 CMS | `cms-現買改資買.html` | 作業端唯讀監控改類名單（單頁；無人工審核） |

**業務規則（已定案於原型）**
- 僅支援「現股買進」→「融資買進」
- 客戶端送出成功即視為通過（全自動）；CMS 不做審核操作
- 對外狀態用語：「已通過」「配額不足」「系統錯誤」「系統管制」
- **未開信用戶**：進入本站即導向信用戶加開（不停留申請頁、不彈雙鈕提示窗）

## 1. CMS｜改類名單（單頁）

### 1.1 功能敘述
作業人員於**同一頁**查詢、匯出線上改類申請名單。  
查詢條件保留**成交日期起迄**；**預設起迄皆為當日（營業日）**。清除後亦回到當日起迄。

### 1.2 查詢條件
| 條件 | 元件 | 說明 |
|---|---|---|
| 成交日期（起） | 日期選擇器 | 預設＝當日 |
| 成交日期（迄） | 日期選擇器 | 預設＝當日 |
| 委託書編號 | 文字 | 模糊比對 |
| ID | 文字 | 身分證字號；模糊比對、不分大小寫；max 10 |
| 委託人帳號 | 文字 | 台股帳號；max 7 |
| 股票名稱／代號 | 文字 | 名稱或代號 |
| 狀態 | 下拉 | 全部／已通過／配額不足／系統錯誤／系統管制 |

操作：清除（回復當日起迄）、查詢、匯出名單（無資料時匯出 disabled）。

### 1.3 列表欄位（左→右）
| 欄位 | 可排序 | 備註 |
|---|---|---|
| 成交日期 | ✓ | 民國年顯示 |
| 委託書編號 | ✓ | |
| ID | ✓ | 身分證 |
| 委託人帳號 | ✓ | |
| 委託人姓名 | ✓ | |
| 股票名稱 | ✓ | 顯示名稱＋代號 |
| B / S | ✗ | |
| 成交張數 | ✓ | |
| 單價 | ✓ | |
| 成交類別 | ✗ | 現買／融資／融券 |
| 更正後張數 | ✓ | 可小於成交張數（部分改類） |
| 更正後類別 | ✗ | |
| 沖抵日期 | ✓ | 民國年顯示 |
| 狀態 | ✓ | 已通過／配額不足／系統錯誤／系統管制 |

### 1.4 其他 UX
- 表頭固定（sticky）
- 分頁：每頁 10 筆
- 匯出 CSV：目前可見欄位＋原因說明；範圍＝篩選後全部（不分頁）
- 已取消「當日／歷史」分頁切換

## 2. 客戶端｜改類申請

### 2.1 功能敘述
用戶於線上指定可改類成交單之改資買張數並送出，無需客服進線。

頁面結構：標題「下單改類申請」；Tab「改類申請｜申請紀錄」；證券帳號唯讀（姓名＋帳號）。

### 2.2 Demo 提示控制（頁頂）
頁面最上方提供 **Demo 控制列**（正式環境應移除）：
- **進場提示**：可辦理／未開信用戶（直轉加開）／融資餘額不足／不跳出（**不隨機**；預設「可辦理」；切換下拉即生效）
- **送出結果**：成功／配額不足／連線異常・系統錯誤／系統管制（**不隨機**；預設「成功」）
- 「立即跳出提示」可重播進場提示；「寫入網址並重載」同步 `?notice=`、`?submit=`

### 2.3 進場檢查與提示視窗

#### A. 未開立信用戶
- **進入本站即導向信用戶加開**（`location.replace`）；不開雙鈕提示窗、不停留申請頁
- 正式 URL：`https://www.labpocket.tw/openaccountonline/oa/login/existing`

#### B. 融資餘額不足（進場）
- 標題：融資餘額不足
- 文案（黑）：您現在融資餘額為 {金額} 元，請調整改資買張數，或前往額度申請提高融資額度
- 文案（紅）：線上額度申請僅限第一類帳戶及第二類帳戶，調整額度需經過元大證金審核，預計審核日為2個工作天
- 按鈕：**回到上一頁**｜前往額度申請
- 回到上一頁：`history.back()`；若無歷史則回官網
- 確定後申請頁鎖定
- ⚠ 額度申請正式 URL 待定；「融資餘額足夠」門檻正式算法待確認

#### C. 可辦理（已開信用且額度足夠）
- 僅「確認」一顆
- 文案（紅）：目前僅支援將「現股買進」變更為「融資買進」。
- 文案：變更前請確認您已開通信用交易資格、融資額度足夠，換行後接「且該檔股票之融資配額張數足夠。」是否確認辦理交易類別變更？
- 確認後可操作申請頁

**共用**：點背景不可關窗；攔截型（B）Esc 視同「回到上一頁」。

### 2.4 查詢與列表

**查詢**：股票代號／名稱關鍵字＋搜尋。

**欄位（左→右）**

| 欄位 | 說明 |
|---|---|
| 委託書號 | 最左欄；可排序 |
| 股票名稱 | 代號＋名稱；可排序 |
| 單價 | 可排序 |
| 今日整股成交張數 | 可排序；**顯示剩餘可改張數**＝整股成交張數 − 改資買張數，隨改資買張數即時更新 |
| 改資買張數 | 可編輯（stepper／輸入）；範圍 0～整股成交張數（上限為原始成交張數） |
| 預估融資金額 | 隨張數即時更新 |

**表尾合計**
- 本次預估融資
- 申請後剩餘額度（剩餘額度 − 本次預估融資）；＜0 時警示樣式

**預估融資計算（現行原型）**  
`單價 × 改資買張數 × 1000`（股／張）

⚠ 若正式規格為「× 該標的今日融資成數」，須改公式並同步改此文件與畫面。

**下一步：送出**
- 至少一筆改資買張數＞0 才可點
- 頁面鎖定或送出中 → disabled

### 2.5 確認改類視窗
觸發：點「下一步：送出」且申請後剩餘額度 ≥ 0。

- 警示：送出後不可更改，請確認改資買張數與金額無誤後再送出。
- 欄位：委託書號、股票名稱、今日整股成交張數（原始成交張數）、改資買張數、預估融資金額
- 表尾：本次預估融資、申請後剩餘額度
- 按鈕：取消（關窗）｜送出申請
- 點背景不關窗；Esc＝取消

### 2.6 送出前額度再檢
若申請後剩餘額度為負數：不開確認窗，改開「融資餘額不足」視窗（文案同 2.3-B）。  
此情境「回到上一頁」／Esc：**只關窗**，不離開頁面、不鎖定，可回表調整張數。

### 2.7 送出結果提示

| 結果 | 文案重點 | 按鈕 | 是否寫入申請紀錄 |
|---|---|---|---|
| 成功 | 已成功送出申請，請稍等5分鐘後至申請紀錄及口袋台股確認 | 我知道了 | ✓ 已通過；並清空張數 |
| 配額不足 | **須顯示配額不足標的**（代號＋名稱，多檔以頓號分隔）；並提示 T+2 交割款／客服 | 我知道了 | ✓ 配額不足 |
| 連線異常／系統錯誤 | 系統錯誤／連線異常，請稍後5分鐘再次申請／客服 | 我知道了 | ✓ 系統錯誤 |
| 系統管制 | 系統管制中，目前無法完成改類申請／客服 | 我知道了 | ✓ 系統管制 |

⚠ 正式 API 判定規則待確認；Demo 以 `?submit=success|source|network|control` 控制（頁頂 Demo 列可切換）。

### 2.8 空狀態
無當日可改類單或超過可改類時間：顯示空頁＋客服電話 0809-089-001；隱藏 Tab。  
⚠ 截止時間（約 15:00）與進場條件正式規則待確認。

## 3. 客戶端｜申請紀錄

### 3.1 功能敘述
用戶查看本人過去改類申請紀錄；可查詢、排序、分頁、匯出。

### 3.2 查詢條件
| 條件 | 元件 |
|---|---|
| 申請日期（起） | 日期選擇器 |
| 申請日期（迄） | 日期選擇器 |
| 股票名稱 | 文字（名稱或代號） |
| 狀態 | 全部／已通過／配額不足／系統錯誤／系統管制 |

操作：清除、查詢、匯出。

### 3.3 主表欄位
申請日期、股票名稱、單價、今日整股成交張數、改資買張數、狀態（皆可排序，改資買張數除外）。

### 3.4 匯出
- 範圍：目前查詢結果全部（不分頁）
- 欄位：申請日期、股票代號、股票名稱、單價、今日整股成交張數、改資買張數、狀態
- 無資料時匯出 disabled

### 3.5 其他 UX
- 分頁：每頁 10 筆
- ⚠ 表頭固定：規格要求 sticky；現行客戶端表頭尚未 sticky（CMS 已有）— 正式是否要補待確認
